Step-by-step walkthrough

  1. Continue from your Lab 05 report.
    1. Open Power BI Desktop.
    2. Open the same Power BI file you completed through Lab 05, from pbi-local\ or your saved workshop solution folder. Keep working in that same file.
    3. Go to the page where margin or sales scenario analysis makes the most sense, such as the Sales and Margin Analysis page.
    4. If you want a safe practice area for optional visuals, duplicate the page first so you can compare the original and experimental versions side by side.
  2. Create the Margin Adjustment % what-if parameter.
    1. On the Modeling ribbon, click New parameter, then click Numeric range.
    2. In the parameter dialog, set Name to Margin Adjustment %.
    3. Set Data type to Decimal number, Minimum to -10, Maximum to 20, Increment to 1, and Default to 0.
    4. Leave Add slicer to this page checked so Power BI creates the slicer and the generated [Margin Adjustment % Value] measure.
    5. Click Create.
    FYI — what a what-if parameter actually creates.
    Margin Adjustment % is really a small disconnected table plus the generated [Margin Adjustment % Value] measure. The slicer changes that selected value, and your scenario measures read it without altering the underlying FactSales data, which makes it safe for side-by-side what-if analysis.
  3. Create the adjusted scenario measures.
    1. On the Home or Modeling ribbon, click New measure.
    2. Create Adjusted Gross Margin so it applies [Margin Adjustment % Value] to the existing margin logic or base [Gross Margin] measure.
    3. Create Adjusted Gross Margin % so it returns the adjusted margin percentage relative to [Sales Amount].
    4. If you want a dynamic label, create the optional Margin Scenario Title measure shown in the answer key below.
    FYI — why scenario logic belongs in measures, not columns.
    [Adjusted Gross Margin] and [Adjusted Gross Margin %] need to recalculate instantly for each slicer choice, territory, product, or date context on the page. A measure can respond to the current [Margin Adjustment % Value]; a calculated column would store one fixed result at refresh time and would not behave like a live scenario.
  4. Add the scenario visuals and confirm they respond to the slicer.
    1. Keep the auto-generated parameter slicer on the page or move it to a clear position near the top.
    2. Add a card for the base [Gross Margin] measure.
    3. Add a second card for [Adjusted Gross Margin].
    4. Add a clustered column chart or line chart that compares the base and adjusted measures by the business dimension you want to explain.
    5. Change the slicer from 0 to a positive and negative value and confirm both cards and the comparison chart update together.
  5. Evaluate the decomposition tree only if it is available in your tenant.
    1. On the Visualizations pane, add a Decomposition tree visual if the visual is available and approved in this environment.
    2. Drag Sales Amount or Gross Margin into Analyze.
    3. Drag Territory, Product Category, Customer Type, and Segment into Explain by.
    4. Try a manual drill path first, then try the AI-driven High value or Low value split only if that option is enabled.
    5. If the visual is unavailable or still marked Verify for Gov, build the fallback instead: a matrix with the same fields nested on rows plus the Lab 4 drillthrough page for detail.
    FYI — decomposition tree manual vs. AI splits.
    A manual path answers a business question you already have, such as breaking Sales Amount down by Territory then Product Category. The AI-driven High value or Low value split instead searches the fields in Explain by for the next branch that most strongly separates the result, which is useful for discovery but still needs human judgment.
  6. Evaluate forecasting or anomaly detection only if available.
    1. Add a line chart with your date field on the X-axis and Sales Amount as the value.
    2. Open the Analytics pane for that visual.
    3. If forecasting is enabled, add a Forecast and set the forecast length and confidence interval for the scenario you want to discuss.
    4. If anomaly detection is enabled on the supported visual, turn it on and review the highlighted points.
    5. If neither feature is approved here, use the fallback path instead: create a rolling-average measure, a prior-period comparison measure, and a threshold flag such as Below 90% of prior period.
    FYI — what forecasting and anomaly detection are assuming.

    These features are not magic predictions; they infer patterns from the history on your line chart and expose how uncertain that inference is.

    • Forecast extends the series based on historical trend and seasonality, so weak or sparse history makes the forecast less trustworthy.
    • Confidence interval shows a likely range, not a guaranteed outcome; wider bands mean more uncertainty.
    • Anomaly detection flags points that differ from the expected pattern, but a flagged point can be either a real business event or just noisy data that needs explanation.
  7. Evaluate Key influencers only if available.
    1. Add a Key influencers visual only if the tenant supports and approves it.
    2. Choose a clear outcome such as a binary Below Target flag or another simple business result.
    3. Add three to five explanatory fields so the visual has meaningful drivers to compare.
    4. Review the ranked influencers and segments with the class, and explicitly discuss correlation versus causation.
    5. If the visual is unavailable, build the fallback instead with ranked visuals, Top N filters, and RANKX-based comparisons from Lab 2.
    FYI — what Key influencers is actually doing.
    The visual statistically compares the chosen outcome, such as a Below Target flag, against the explanatory fields you provide and ranks the factors most associated with a higher or lower likelihood of that outcome. It is great for surfacing patterns to investigate, but it does not prove that a field caused the result, which is why the lab explicitly calls out correlation versus causation.
  8. Keep Python/R and Azure ML as optional review topics unless validated.

    Do not enable Python/R visuals or Azure ML integration unless runtime approval, package approval, Service support, network egress, identity, region, and data residency have all been validated for this tenant. If those checks are not complete, stay on the Gov-safe path with native visuals or a static pre-scored sample output.

    FYI — why governed AI prerequisites matter.
    Python/R visuals and Azure ML can introduce package risk, outbound connectivity, identity dependencies, and data-movement questions that do not exist with native visuals alone. In a regulated tenant, the technical feature may work but still be unacceptable until security, region, and residency controls are proven.
  9. Keep Copilot conceptual unless the tenant is validated for it.

    If Copilot for Power BI or Fabric has not been validated here, explain the use case conceptually only: what it might summarize, what a prompt might ask, and why every AI-generated measure or narrative still requires human review before it is trusted or shared.

    FYI — why human review is still required for AI outputs.
    A generated narrative, measure, or explanation may sound confident while still misreading the business meaning of [Gross Margin], [Sales Amount], or the current filter context. Treat AI as a drafting aid: useful for speed, but never the final authority for numbers that will be shared with stakeholders.

Answer key

Show what-if parameter DAX pattern

Power BI may generate slightly different names for the parameter table and selected-value measure. Adjust names to match your model.

// Generated or equivalent selected value measure
Margin Adjustment % Value =
SELECTEDVALUE ( 'Margin Adjustment %'[Margin Adjustment %], 0 )

Adjusted Gross Margin =
VAR AdjustmentRate =
    DIVIDE ( [Margin Adjustment % Value], 100 )
RETURN
    [Gross Margin] * ( 1 + AdjustmentRate )

Adjusted Gross Margin % =
DIVIDE ( [Adjusted Gross Margin], [Sales Amount] )

Margin Scenario Title =
VAR Adjustment =
    FORMAT ( DIVIDE ( [Margin Adjustment % Value], 100 ), "0%" )
RETURN
    "Margin scenario: " & Adjustment

Azure Government note

Use the Gov-ready path by default. Features marked Verify for Gov or Commercial-focused require tenant, licensing, capacity, network, identity, or policy validation before hands-on delivery.

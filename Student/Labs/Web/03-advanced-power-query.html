Step-by-step walkthrough

  1. Open or create your Power BI file, then open Power Query Editor.
    1. Open Power BI Desktop.
    2. If you are continuing the workshop solution, open the file in pbi-local\; otherwise create a new blank Power BI file first.
    3. On the Home ribbon, click Transform data to open Power Query Editor.
  2. Create the five Lab 03 parameters before you import data.
    1. In Power Query Editor, click Home > Manage Parameters > New Parameter.
    2. Create the first parameter, click OK, then repeat the same command until all five parameters below exist.
    3. Leave SourceFolderPath blank unless you are intentionally demonstrating an offline local-folder alternative.
    ParameterTypeSuggested valueUsed in core Web path?Purpose
    RawDataBaseUrlTexthttps://raw.githubusercontent.com/Coding-Forge/PBI-Advanced-Factory/main/data/YesBase path for raw GitHub CSV files.
    SourceFolderPathTextBlank, or a local folder path for offline deliveryNoOptional folder connector placeholder for instructor/offline scenarios.
    EnvironmentNameText or ListDevYes, as documentation/conceptIntroduces Dev/Test/Prod source switching without changing the required Web-source path.

    FYI — why parameterize sources.
    Parameters such as RawDataBaseUrl, EnvironmentName, RangeStart, and RangeEnd keep the M logic reusable instead of hardcoding values in multiple queries. When the file location or refresh window changes, you update one controlled input instead of editing every Web.Contents or filter step by hand. That lowers maintenance risk and makes the query behavior easier to explain and test.
  3. Import orders-2026-01.csv from the web.
    1. In Power Query Editor, click Home > New Source > Web.
    2. Paste the orders-2026-01.csv URL from the Source files section above, then click OK.
    3. If prompted for authentication, choose Anonymous and click Connect.
    4. Rename the new query raw_Orders_2026_01.
  4. Import orders-2026-02.csv from the web.
    1. Click Home > New Source > Web.
    2. Paste the orders-2026-02.csv URL from the Source files section, then click OK.
    3. Choose Anonymous and click Connect if the credential prompt appears again.
    4. Rename the new query raw_Orders_2026_02.
  5. Import orders-2026-03.csv from the web.
    1. Click Home > New Source > Web.
    2. Paste the orders-2026-03.csv URL from the Source files section, then click OK.
    3. Choose Anonymous and click Connect if prompted.
    4. Rename the new query raw_Orders_2026_03.
  6. Review the generated M steps before you transform anything.

    Turn on the formula bar if it is hidden, then inspect how each query uses steps such as Source and Promoted Headers. Call out that M can work with records and lists as well as tables, which becomes important when you use Csv.Document, parameters, and Table.Combine.

  7. Add source-lineage columns to the raw monthly queries.
    1. Select raw_Orders_2026_01.
    2. Click Add Column > Custom Column, name the column SourceFile, enter the file name orders-2026-01.csv as the custom value, then click OK.
    3. Repeat the same Add Column > Custom Column flow in raw_Orders_2026_02 and raw_Orders_2026_03, using the matching file name in each query.
  8. Append the monthly queries into one staging query.
    1. On the Home ribbon, click Append Queries > Append Queries as New.
    2. Choose Three or more tables.
    3. Add raw_Orders_2026_01, raw_Orders_2026_02, and raw_Orders_2026_03 to the append list in month order.
    4. Click OK, then rename the appended query stg_OrdersCombined.
    5. Confirm the appended result keeps a consistent schema across all three files.
    FYI — append vs. merge.
    Appending stacks rows from raw_Orders_2026_01, raw_Orders_2026_02, and raw_Orders_2026_03 into one longer fact-style table, which is exactly what monthly snapshots need. A merge is different: it joins columns from another table based on matching keys. If you used merge here, you would widen the dataset instead of building the combined transaction history needed for FactOrders.
  9. Create the reusable text-cleanup function and invoke it where needed.
    1. Click Home > New Source > Blank Query.
    2. Rename the query fn_CleanText.
    3. Open Home > Advanced Editor, paste the function from the answer key, then click Done.
    4. Invoke the function for CustomerName and SalesChannel in FactOrders.
    5. Invoke the same function for ProductName, ProductCategory, and ProductSubcategory in dim_ProductCategory.
    FYI — why turn cleanup logic into fn_CleanText.
    Putting trim/clean/proper-case logic in a function gives FactOrders and dim_ProductCategory one shared definition of "clean text." If you later change the rule, you update the function once instead of hunting through several separate custom steps. This also demonstrates that Power Query can package repeated logic into reusable M functions, not just click-generated table steps.
  10. Create err_OrdersReview so invalid rows stay reviewable.
    1. Right-click stg_OrdersCombined and choose Reference.
    2. Rename the new query err_OrdersReview.
    3. Add a DataQualityIssue column that records readable reasons such as missing or invalid OrderDate, missing or non-positive Quantity, missing or non-positive UnitPrice, and missing ProductCode.
    4. Filter the query so only rows with a populated DataQualityIssue remain.
    5. Use column quality or column profile views to confirm the intentional bad rows from the March file are visible here.
    FYI — why separate error review from the final fact.
    Referencing stg_OrdersCombined into err_OrdersReview preserves bad rows for investigation instead of silently deleting them. The try ... otherwise pattern lets you test values such as OrderDate, Quantity, and UnitPrice without breaking refresh when one row is malformed. This is safer than only using Remove Errors, which can hide data-quality problems with no explanation.
  11. Create the final FactOrders query from the staging query.
    1. Right-click stg_OrdersCombined and choose Reference.
    2. Rename the new query FactOrders.
    3. Add the same DataQualityIssue logic used in err_OrdersReview.
    4. Filter the query so only rows where DataQualityIssue is blank remain.
    5. Apply explicit data types for OrderId, OrderDate, CustomerName, ProductCode, Quantity, UnitPrice, SalesChannel, and SourceFile.
    6. Apply fn_CleanText to the customer and channel text columns before you close the editor.
  12. Load product-category-map.csv and build dim_ProductCategory.
    1. Click Home > New Source > Web.
    2. Paste the product-category-map.csv URL from the Source files section, then click OK.
    3. Choose Anonymous and click Connect if prompted.
    4. Rename the new query dim_ProductCategory.
    5. Keep the model-ready columns ProductCode, ProductName, ProductCategory, and ProductSubcategory, then apply fn_CleanText to the text fields.
  13. Disable load for intermediate queries and document the staged architecture.
    1. Right-click each raw query, stg_OrdersCombined, err_OrdersReview, and fn_CleanText.
    2. Clear Enable load for those intermediate objects.
    3. Leave FactOrders and dim_ProductCategory enabled for load.
    4. Keep the required Web-source queries pointed at RawDataBaseUrl, and use EnvironmentName plus optional SourceFolderPath only to document how Dev/Test/Prod or offline delivery would be handled.
    QuerySourceLoad enabled?Required output
    raw_Orders_2026_01orders-2026-01.csv Web URLNoAll source columns plus SourceFile.
    raw_Orders_2026_02orders-2026-02.csv Web URLNoAll source columns plus SourceFile.

    FYI — why disable load on raw and staging queries.
    Queries such as raw_Orders_2026_01, stg_OrdersCombined, err_OrdersReview, and fn_CleanText exist to support preparation, validation, and reuse—not to become report tables. Leaving load enabled would clutter the model and can increase refresh and memory usage with duplicate intermediate data. The staged pattern keeps only business-ready tables like FactOrders and dim_ProductCategory visible to report authors.
  14. Filter FactOrders with RangeStart and RangeEnd for incremental refresh preparation.
    1. Select the FactOrders query.
    2. Open the filter on OrderDate.
    3. Apply a filter that keeps rows on or after RangeStart and before RangeEnd.
    4. Confirm the filtered column is Date/Time-compatible so the query is ready for later incremental refresh policy setup.

    Desktop preparation is the required part of this lab. Service-side incremental refresh configuration remains Verify for Gov.

    FYI — why RangeStart and RangeEnd matter.
    These parameters mark the date window Power BI can later partition for incremental refresh, so only newer slices of FactOrders need to be reprocessed. The filter must be on the actual date column and use the parameter values directly, or the service may not recognize the pattern. Even though the policy is configured later, this Power Query step is what makes the dataset eligible for that optimization.
  15. Review query-folding and native-query limitations in context.

    Explain that file-based Web CSV imports do not provide the same folding behavior as SQL or other folding-capable sources, so View Native Query is only meaningful when you also test a connector that supports folding in the target environment. Keep native SQL optional and prefer maintainable Power Query steps for the core lab.

    FYI — why query folding is still worth teaching here.
    Folding means Power Query can push transforms back to the source, which is usually faster and reduces data movement. These Web CSV files do not really fold, so the lesson is not "make this source fold"—it is "recognize when a source cannot fold, and avoid assuming every connector behaves like SQL." That helps students understand why step order and source choice matter so much in larger production datasets.

Answer key

Show Power Query M patterns

These snippets show the intended M patterns. Your generated step names may differ depending on how you clicked through Power Query.

// Parameter value
RawDataBaseUrl = "https://raw.githubusercontent.com/Coding-Forge/PBI-Advanced-Factory/main/data/"

// Optional offline/folder delivery placeholder
SourceFolderPath = ""

// Environment documentation/concept parameter
EnvironmentName = "Dev"

// Incremental refresh preparation parameters
RangeStart = #datetime(2026, 1, 1, 0, 0, 0)
RangeEnd = #datetime(2026, 4, 1, 0, 0, 0)

// Example Web source pattern
Source =
    Csv.Document(
        Web.Contents(RawDataBaseUrl & "monthly-orders/orders-2026-01.csv"),
        [Delimiter = ",", Encoding = 65001, QuoteStyle = QuoteStyle.Csv]
    )

PromotedHeaders =
    Table.PromoteHeaders(Source, [PromoteAllScalars = true])

WithSourceFile =
    Table.AddColumn(
        PromotedHeaders,
        "SourceFile",
        each "orders-2026-01.csv",
        type text
    )

// Append pattern
stg_OrdersCombined =
    Table.Combine({
        raw_Orders_2026_01,
        raw_Orders_2026_02,
        raw_Orders_2026_03
    })

// Text cleanup function
(inputText as nullable text) as nullable text =>
let
    Result =
        if inputText = null then
            null
        else
            Text.Proper(Text.Trim(Text.Clean(inputText)))
in
    Result

// Error review query pattern
err_OrdersReview =
    let
        Source = stg_OrdersCombined,
        AddedDataQualityIssue =
            Table.AddColumn(
                Source,
                "DataQualityIssue",
                each
                    let
                        ParsedOrderDate = try Date.From([OrderDate]) otherwise null,
                        ParsedQuantity = try Number.From([Quantity]) otherwise null,
                        ParsedUnitPrice = try Number.From([UnitPrice]) otherwise null,
                        ProductCodeText = try Text.Trim(Text.From([ProductCode])) otherwise "",
                        Issues =
                            List.RemoveNulls(
                                {
                                    if ParsedOrderDate = null then "Missing or invalid OrderDate" else null,
                                    if ParsedQuantity = null or ParsedQuantity <= 0 then "Missing or non-positive Quantity" else null,
                                    if ParsedUnitPrice = null or ParsedUnitPrice <= 0 then "Missing or non-positive UnitPrice" else null,
                                    if ProductCodeText = "" then "Missing ProductCode" else null
                                }
                            )
                    in
                        Text.Combine(Issues, "; "),
                type text
            ),
        ErrorRows =
            Table.SelectRows(
                AddedDataQualityIssue,
                each [DataQualityIssue] <> ""
            )
    in
        ErrorRows

// FactOrders valid-row filter pattern
ValidatedOrders =
    Table.AddColumn(
        stg_OrdersCombined,
        "DataQualityIssue",
        each
            let
                ParsedOrderDate = try Date.From([OrderDate]) otherwise null,
                ParsedQuantity = try Number.From([Quantity]) otherwise null,
                ParsedUnitPrice = try Number.From([UnitPrice]) otherwise null,
                ProductCodeText = try Text.Trim(Text.From([ProductCode])) otherwise "",
                Issues =
                    List.RemoveNulls(
                        {
                            if ParsedOrderDate = null then "Missing or invalid OrderDate" else null,
                            if ParsedQuantity = null or ParsedQuantity <= 0 then "Missing or non-positive Quantity" else null,
                            if ParsedUnitPrice = null or ParsedUnitPrice <= 0 then "Missing or non-positive UnitPrice" else null,
                            if ProductCodeText = "" then "Missing ProductCode" else null
                        }
                    )
            in
                Text.Combine(Issues, "; "),
        type text
    )

ValidRows =
    Table.SelectRows(
        ValidatedOrders,
        each [DataQualityIssue] = ""
    )

// Final type pattern
TypedOrders =
    Table.TransformColumnTypes(
        ValidRows,
        {
            {"OrderId", Int64.Type},
            {"OrderDate", type date},
            {"CustomerName", type text},
            {"ProductCode", type text},
            {"Quantity", Int64.Type},
            {"UnitPrice", Currency.Type},
            {"SalesChannel", type text},
            {"SourceFile", type text}
        }
    )

// Invoke fn_CleanText in FactOrders after typing
FactOrders =
    Table.TransformColumns(
        TypedOrders,
        {
            {"CustomerName", each fn_CleanText(_), type nullable text},
            {"SalesChannel", each fn_CleanText(_), type nullable text}
        }
    )

// Invoke fn_CleanText in the product reference query
CleanedProductText =
    Table.TransformColumns(
        dim_ProductCategory,
        {
            {"ProductName", each fn_CleanText(_), type nullable text},
            {"ProductCategory", each fn_CleanText(_), type nullable text},
            {"ProductSubcategory", each fn_CleanText(_), type nullable text}
        }
    )

// Incremental refresh filter pattern
FilteredRows =
    Table.SelectRows(
        FactOrders,
        each [OrderDate] >= Date.From(RangeStart)
            and [OrderDate] < Date.From(RangeEnd)
    )

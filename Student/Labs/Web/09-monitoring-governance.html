Detailed step-by-step procedure

  1. Start from a published report.

    Use the report and semantic model published in Lab 8, or follow an instructor demo if you do not have workspace access.

  2. Open usage metrics.

    Review views, unique viewers, page usage, and trends. Document adoption observations and one follow-up action.

  3. Review refresh history.

    Open the semantic model refresh history. Record the last status, duration, and any failure details.

  4. Check credentials and source settings.

    Review data source credentials, privacy settings, and whether a gateway is required. Do not change production settings unless approved.

  5. Review tenant settings.

    If you have admin access, review sharing, export, publish-to-web, certification, external users, and Build permission settings. Otherwise, use instructor screenshots or conceptual review.

  6. Inspect gateway health where available.

    Review gateway cluster status, data source mappings, credential ownership, version, and escalation path.

  7. Review optional admin signals.

    Activity logs, audit logs, admin monitoring workspace, capacity metrics, Purview, and DLP require permissions and tenant validation. Record what is available and what is blocked.

  8. Complete the operations runbook.

    Document content inventory, owners, sources, refresh schedule, access model, monitoring cadence, incident response, and Azure Government validation notes.

  9. Define support process.

    Identify who handles refresh failures, access issues, data quality problems, performance issues, and enhancement requests.

  10. Document gaps.

    For anything you cannot access, document the validation gap and the owner who can confirm it later.

Azure Government note

Use the Gov-ready path by default. Features marked Verify for Gov or Commercial-focused require tenant, licensing, capacity, network, identity, or policy validation before hands-on delivery.

Novice-friendly how-to guide

Use Performance Analyzer

  1. Open the report page to test.
  2. Select View > Performance Analyzer.
  3. Select Start recording.
  4. Refresh visuals or interact with slicers.
  5. Expand each visual result and record DAX query time, visual display time, and other time.

Reduce model size

  1. Review columns in Data or Model view.
  2. Identify columns not used in relationships, measures, slicers, or visuals.
  3. Remove unused columns in Power Query, not just hide them.
  4. Reduce precision or split DateTime columns only when the report does not need full detail.

Optimize a measure with variables

  1. Copy the original measure to a notes area before changing it.
  2. Create variables with VAR for repeated expressions.
  3. Return the final result with RETURN.
  4. Compare old and new results in the same visual.

Detailed step-by-step procedure

  1. Open the current report PBIP.

    Use the report built in the previous labs. Choose one report page that has several visuals and slicers.

  2. Capture a baseline.

    Open View > Performance Analyzer. Start recording, refresh visuals, interact with slicers, and record which visuals have high DAX query time or rendering time.

  3. Review visual complexity.

    Count visuals on the page. Identify visuals that duplicate information, use high-cardinality fields, or are not needed for the page objective.

  4. Review model fields.

    Inspect fact and dimension tables for unused columns, high-cardinality text, excessive precision, and date/time fields that could be simplified.

  5. Optimize one DAX measure.

    Choose a measure with repeated expressions or broad filter removal. Rewrite it using variables and measure branching, then compare results before and after.

  6. Optimize visuals.

    Remove or consolidate at least one low-value visual. Disable unnecessary visual interactions if cross-filtering creates extra query load without helping the user.

  7. Review aggregation design.

    Define a possible aggregation grain such as Month, Product Category, and Territory. Document whether the detail table would remain Import or DirectQuery.

  8. Review incremental refresh.

    Confirm which fact date column would support partitioning. Document RangeStart/RangeEnd requirements and whether Service support is validated.

  9. Optional external diagnostics.

    If DAX Studio or VertiPaq Analyzer is approved, connect and compare timings/model size. If not, keep this step conceptual and mark Verify for Gov.

  10. Document results.

    Record baseline, change made, after result, tradeoff, and remaining risk. Do not claim improvement without evidence.

Answer key

Show sample DAX optimization pattern

Use this as a pattern for simplifying repeated measure logic. Your exact measure may vary.

// Less maintainable pattern
Sales Variance % - Repeated =
DIVIDE (
    SUM ( FactSales[SalesAmount] )
        - SUM ( FactTargets[TargetSalesAmount] ),
    SUM ( FactTargets[TargetSalesAmount] )
)

// Preferred measure-branching pattern
Sales Amount =
SUM ( FactSales[SalesAmount] )

Target Sales Amount =
SUM ( FactTargets[TargetSalesAmount] )

Sales Variance =
[Sales Amount] - [Target Sales Amount]

Sales Variance % =
VAR VarianceAmount = [Sales Variance]
VAR TargetAmount = [Target Sales Amount]
RETURN
    DIVIDE ( VarianceAmount, TargetAmount )

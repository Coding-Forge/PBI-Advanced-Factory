Detailed step-by-step procedure

  1. Confirm workspace access.

    Identify the training workspace and your role. You need appropriate permission to publish, configure refresh, or create Apps.

  2. Publish the PBIP-authored report.

    Open the report in Power BI Desktop and publish to the training workspace. Verify both the report and semantic model appear in the Service.

  3. Review semantic model settings.

    Open semantic model settings. Review data source credentials, privacy settings, refresh history, and ownership.

  4. Configure scheduled refresh where supported.

    Set credentials and a refresh schedule. If the data source uses raw GitHub URLs, validate anonymous Web refresh behavior in the Service.

  5. Document gateway requirements.

    If a source is on-premises or network-restricted, identify gateway cluster, data source mapping, credentials, and owner. If no gateway is needed, document why.

  6. Create a thin report scenario.

    Grant Build permission where appropriate and create or discuss a thin report connected to the shared semantic model.

  7. Package as an App.

    Select workspace content, configure name/description/navigation, assign consumers, publish or update the App, and validate consumer experience.

  8. Review App audiences.

    If available, create multiple audiences and tailor content. If not validated, keep this optional and mark Verify for Gov.

  9. Review deployment pipelines.

    If available, map dev/test/prod workspaces and review deployment rules. If unavailable, document the manual promotion path.

  10. Complete endorsement checklist.

    Review ownership, refresh, security, quality, and support evidence before marking content Promoted or Certified.

Azure Government note

Use the Gov-ready path by default. Features marked Verify for Gov or Commercial-focused require tenant, licensing, capacity, network, identity, or policy validation before hands-on delivery.

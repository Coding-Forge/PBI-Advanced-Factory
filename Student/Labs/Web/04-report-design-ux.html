Lab 4 - Guided report experience

Report Design and UX

Design audience-focused report pages with clear filters, drillthrough, tooltips, bookmarks, navigation, field parameters, conditional formatting, mobile layout, and accessibility review.

Advanced authoringDeliverable: Interactive report pagesPower BI file

What you will produce

  • Audience-focused pages
  • Drillthrough details
  • Report page tooltip
  • Bookmarks and navigation
  • Field parameters and selectors
  • Mobile and accessibility review

Step-by-step walkthrough

  1. Open the report file from the earlier labs and confirm the model is ready.
    1. Open Power BI Desktop.
    2. Open the workshop file from pbi-local\, using the semantic model from Lab 01 and the measures from Lab 02.
    3. In the Fields pane, confirm measures such as [Sales Amount], [Gross Margin], [Gross Margin %], [Sales Variance], and [Quantity] are available before you build report pages.
  2. Plan the report surfaces before you place visuals.
    1. List the audience for each page: executive, analyst, and operational/detail.
    2. Write one decision question per page so every visual supports a clear purpose.
    3. Keep slicer placement and naming consistent across pages so users can understand report context quickly.

    FYI — why page purpose matters.
    A page should answer one clear decision question, otherwise users get a crowded canvas that mixes executive KPIs, analyst exploration, and operational actions together. Separating Executive Summary, Analyst Exploration, and Customer Detail keeps the filter context understandable and makes each page easier to scan. Good UX in Power BI starts with information hierarchy, not with formatting.
  3. Create the Executive Summary page.
    1. Right-click an existing page tab and choose Insert page.
    2. Double-click the new page tab and rename it Executive Summary.
    3. In the Visualizations pane, click the Card icon to drop a blank card visual on the canvas, then drag [Sales Amount] into the Fields well. Repeat this three more times so you have four separate cards for [Sales Amount], [Gross Margin %], [Sales Variance], and [Quantity].
    4. Resize each card so they are the same height and arrange them left to right in a single row across the top of the canvas, in the order listed above.
    5. Click the Line chart icon in the Visualizations pane to add a new visual below the card row. Drag DimDate[Date] (or your date table's month/date field) into the X-axis well and drag [Sales Amount] into the Y-axis well.
    6. Resize the line chart so it spans most of the width of the canvas, directly under the KPI cards.
    7. Add one more visual for a high-level breakdown, such as a Clustered bar chart: drag DimTerritory[TerritoryRegion] into the Y-axis well and [Sales Amount] into the X-axis well. Place this visual under or beside the line chart so the page tells one connected story.
  4. Create the Analyst Exploration page.
    1. Insert another new page and rename it Analyst Exploration.
    2. Add five Slicer visuals: click the Slicer icon once per field, then drag in one of DimDate[OrderDate], DimTerritory[TerritoryRegion], DimProductCategory[ProductCategory], DimCustomer[CustomerName], and DimSegment[Segment] per slicer. Line them up across the top of the canvas or stack them down one side.
    3. Click the Matrix icon to add a matrix visual. Drag DimCustomer[CustomerName], DimProductCategory[ProductCategory], DimTerritory[TerritoryRegion], and DimSegment[Segment] into the Rows well, and drag [Sales Amount] into the Values well so analysts can compare across all four dimensions.
    4. Add at least one chart, such as a Clustered column chart, with DimDate[OrderDate] (or month) in the X-axis well and [Sales Amount] in the Y-axis well, so the same five slicers filter both the matrix and this chart together.
  5. Create the operational or detail page for action monitoring.
    1. Insert another page and give it a plain descriptive name that matches its action question.
    2. Add monitoring visuals such as a Table or Line chart visual to track a key measure over time, plus an exception list: add a Table visual and drag in DimCustomer[CustomerName], DimDate[OrderDate], and [Sales Variance], then use the Filters pane to keep only rows where [Sales Variance] is below zero (or another threshold) so the table only shows the records needing attention.
    3. Keep this page focused on one action-oriented workflow instead of repeating the executive summary.
  6. Validate slicers, page filters, and report context.
    1. Click each slicer one at a time and confirm only the intended visuals change.
    2. Open the Filters pane and use page-level filters where a filter should apply to the whole page.
    3. Move or relabel slicers if a new learner could not quickly tell which filters are active.
  7. Create the Customer Detail drillthrough page.
    1. Insert a new page and rename it Customer Detail.
    2. In the Visualizations pane, find the Drill through field well.
    3. Drag DimCustomer[CustomerName] into the drillthrough field well.
    4. Confirm Keep all filters matches your design intent.
    5. Add customer KPI cards and a transaction table to the page: add two Card visuals for [Sales Amount] and [Quantity], then add a Table visual and drag in DimDate[OrderDate], DimProduct[ProductName], [Sales Amount], and [Quantity] so it lists that customer's individual transactions.
    6. Add a back button with Insert > Buttons > Back or set a button action to Back.
    7. Test the page by right-clicking a customer value on another page and selecting Drill through > Customer Detail.
    FYI — how drillthrough passes context.
    Drillthrough automatically carries the selected DimCustomer[CustomerName] value to the target page, which is why the detail page opens already filtered to that customer. Keep all filters decides whether the rest of the source-page context—such as date, territory, or product slicers—travels too. Use drillthrough when a user needs a focused deep dive from one data point, not just a different visual state on the same page.
  8. Create the Sales Tooltip report page tooltip.
    1. Insert a new page and rename it Sales Tooltip.
    2. Open the page formatting settings and set the page type or page size to Tooltip.
    3. Turn on Allow use as tooltip.
    4. Add compact KPI cards and a small trend visual sized to fit the tooltip canvas: add two small Card visuals for [Sales Amount] and [Gross Margin %], and add a small Line chart with DimDate[Date] in the X-axis well and [Sales Amount] in the Y-axis well, then resize all three so they fit the small tooltip canvas.
    5. Return to the main report page, select the visual that should use this tooltip, then set Format > General > Tooltips to Report page and choose Sales Tooltip.
    FYI — why use a report page tooltip.
    A report page tooltip gives extra context at the exact point of hover without forcing the user to leave the current visual. That makes it ideal for compact details such as a small sales trend or supporting KPIs that would otherwise clutter Executive Summary. Unlike drillthrough, a tooltip is for quick inspection, not navigation.
  9. Add bookmarks and button-driven guided interactions.
    1. Open View > Bookmarks to show the Bookmarks pane.
    2. Set the visuals or filters to the state you want to capture, then click Add.
    3. Rename the bookmark clearly, such as Show Detail Panel or Reset Filters.
    4. Right-click the bookmark and confirm whether Data, Display, and Current page should be checked.
    5. Add a button or shape, turn on Action, set the action type to Bookmark, and point it at the correct bookmark.
    FYI — what a bookmark actually captures.
    A bookmark can store more than visual visibility: it can also store filter/slicer state (Data) and the active page (Current page). That is why the checkbox choices matter so much—if you save too much state, a simple Reset Filters button can accidentally move users or hide visuals they did not expect. Use bookmarks for guided report states; use drillthrough when the goal is page-to-page detail based on a selected data point.
  10. Add consistent navigation across report pages.
    1. Insert a page navigator with Insert > Buttons > Navigator > Page navigator, or add individual buttons with action type Page navigation.
    2. Place the navigator in the same position on every page.
    3. Use plain labels that match the visible page names.
    4. Test navigation from every page so users are not forced to rely on page tabs only.
  11. Create Metric Parameter and optionally Dimension Parameter.
    1. Click Modeling > New parameter > Fields.
    2. Name the parameter Metric Parameter.
    3. Select [Sales Amount], [Gross Margin], [Gross Margin %], and [Quantity].
    4. Leave Add slicer to this page checked, then click Create.
    5. Replace a single-measure visual value with the generated Metric Parameter field and test the slicer.
    6. If you want a dimension switcher, repeat the same command to create Dimension Parameter with DimProductCategory[ProductCategory], DimTerritory[TerritoryRegion], and DimSegment[Segment].
    FYI — what field parameters solve.
    Metric Parameter lets one visual switch between [Sales Amount], [Gross Margin], [Gross Margin %], and [Quantity] without duplicating four separate charts. Power BI creates a helper table behind the scenes, so the slicer is driving which field the visual uses rather than filtering fact rows directly. This keeps the page cleaner while still giving analysts controlled flexibility.
  12. Apply threshold-based conditional formatting.
    1. Choose a business threshold, such as negative [Sales Variance] or low [Gross Margin %].
    2. Select the visual, open the field dropdown, and choose Conditional formatting.
    3. Configure background color, font color, or icons using the chosen measure and threshold.
    4. Add a text label, legend, icon, or status field so color is not the only cue.

    If time allows, complete the disconnected margin-target challenge so the selected target, variance-to-target, and color logic stay aligned.

    FYI — why conditional formatting needs business meaning.
    Threshold colors only help when they represent a rule users can explain, such as negative [Sales Variance] or an unacceptable [Gross Margin %]. If the threshold is arbitrary, the report looks polished but does not guide action. Adding text, icons, or labels ensures the message still works for users with color-vision differences or when the report is printed.
  13. Create the mobile layout.
    1. Click View > Mobile layout.
    2. Drag the highest-value visuals onto the mobile canvas in priority order.
    3. Resize and reorder the visuals so touch targets are large and readable.
    4. Keep dense tables off the phone layout unless the audience specifically needs them there.
  14. Run the accessibility review before you finish.
    1. Select each visual and add descriptive alt text in the Format pane.
    2. Open View > Selection and arrange objects into a logical tab order.
    3. Check contrast, confirm every visual title is descriptive, and avoid color-only meaning.
    4. Use keyboard navigation to confirm the report flow is understandable without a mouse.
    FYI — accessibility improves usability for everyone.
    Alt text, tab order, contrast, and descriptive titles are not just compliance tasks—they make the report easier to navigate, explain, and present. A clear keyboard path often exposes cluttered layouts or ambiguous labels that also confuse sighted mouse users. Treat accessibility review as a final UX quality check, not as a separate afterthought.

Deeper Understanding Challenge

Build a disconnected metric selector

Compare native field parameters with a Power Query selector table and a DAX SWITCH measure.

  1. Create a blank Power Query named Metric Selector.
  2. Use #table to create rows for Sales Amount, Gross Margin, Gross Margin %, and Quantity.
  3. Load the table without relationships.
  4. Create Selected Metric Value using SELECTEDVALUE and SWITCH.
let
    Source =
        #table(
            type table [Metric = text, SortOrder = Int64.Type],
            {
                {"Sales Amount", 0},
                {"Gross Margin", 1},
                {"Gross Margin %", 2},
                {"Quantity", 3}
            }
        )
in
    Source
Selected Metric Value =
VAR SelectedMetric =
    SELECTEDVALUE ( 'Metric Selector'[Metric], "Sales Amount" )
RETURN
    SWITCH (
        SelectedMetric,
        "Sales Amount", [Sales Amount],
        "Gross Margin", [Gross Margin],
        "Gross Margin %", [Gross Margin %],
        "Quantity", [Quantity],
        [Sales Amount]
    )

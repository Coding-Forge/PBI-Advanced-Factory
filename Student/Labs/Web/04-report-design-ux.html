Lab 4 - Guided report experience

Report Design and UX

Build five pages of the AzureGov report click by click: Executive Overview, Sales & Margin Analysis, Customer & Segmentation Detail, Hierarchies, Drill & Groups, and Sales Detail Tooltip — with drillthrough, report page tooltips, bookmarks, navigation, field parameters, what-if parameters, conditional formatting, mobile layout, and accessibility review. The Security, Navigation & Tooltip page is built in Lab 07 alongside row-level security.

What you will produce

  • Audience-focused pages
  • Drillthrough details
  • Report page tooltip
  • Bookmarks and navigation
  • Field parameters and selectors
  • Mobile and accessibility review

Step-by-step walkthrough

  1. Open the AzureGov report file and confirm the model is ready.
    1. Open Power BI Desktop.
    2. Choose File > Open and browse to pbi-local\AzureGov\AdvancedPBI.pbip, which uses the semantic model from Lab 01 and the measures from Lab 02.
    3. In the Fields pane, expand _Measures and confirm [Sales Amount], [Gross Margin], [Gross Margin %], [Order Count], [Quantity], [Sales Variance], and [Sales YoY %] are available.
    4. Confirm the dimension tables DimCustomer, DimTerritory, DimProduct (with its Product Hierarchy), DimProductCategory, DimSegment, DimOrderDate, and DimShipDate are all present before you build report pages.
  2. Plan the report surfaces before you place visuals.
    1. List the audience for each page: executive, analyst/margin, customer, product, security, and support.
    2. Write one decision question per page so every visual supports a clear purpose.
    3. Keep slicer placement and naming consistent across pages so users can understand report context quickly.

    FYI — why page purpose matters.
    A page should answer one clear decision question, otherwise users get a crowded canvas that mixes executive KPIs, margin scenarios, and customer detail together. Separating Executive Overview, Sales & Margin Analysis, and Customer & Segmentation Detail keeps the filter context understandable and makes each page easier to scan. Good UX in Power BI starts with information hierarchy, not with formatting.
  3. Create the Executive Overview page.
    1. Right-click an existing page tab and choose Insert page.
    2. Double-click the new page tab and rename it Executive Overview.
    3. Add a Card visual near the top-left as a dynamic header: drag in the [Dynamic Title] measure, then in the Format pane turn off Category label and increase the callout value font size. Because [Dynamic Title] is built from "Sales Overview — " & [Selected Territory Or Region], the header text will change automatically as users pick a territory.
    4. Add four Card visuals in a single row below the header: drag in [Sales Amount], [Gross Margin %], [Order Count], and [Sales YoY %] — one measure per card, left to right in that order.
    5. In the Format pane for each card, open General > Properties and add descriptive alt text such as Sales amount KPI, Gross margin KPI, Order count KPI, and Year over year KPI.
    6. Add a Slicer visual in the top-right corner and drag in DimOrderDate[Date].
    7. Add a second Slicer visual beside it and drag in DimTerritory[TerritoryRegion].
    8. Add a Matrix visual under the two slicers: drag DimTerritory[TerritoryRegion] and DimTerritory[TerritoryName] into the Rows well, and drag [Sales Amount] and [Gross Margin %] into the Values well.
    9. Add a Line and stacked column chart (combo chart) below the KPI cards: drag DimOrderDate[Year] and then DimOrderDate[Date] into the X-axis well (in that order, so Year is the outer level), drag [Sales Amount] into Column Y-axis, and drag [Sales Variance %] into Line Y-axis.
    10. Add alt text to the combo chart, such as Trend chart comparing YTD, prior year, and YoY performance.
    FYI — why a card can act as a page title.
    A Card visual bound to a text measure like [Dynamic Title] reacts to slicers the way a real visual does, while a plain textbox cannot. This is why the Executive Overview header changes to reflect the selected territory instead of staying static — the same trick used for [Selected Territory Or Region] anywhere else you want a headline that responds to filters.
  4. Create the Sales & Margin Analysis page.
    1. Insert another new page and rename it Sales & Margin Analysis.
    2. Add a Textbox near the top-left with the bold heading text Sales & Margin Analysis.
    3. Create the first what-if input as a manual disconnected table: open Home > Transform data, choose New source > Blank table (or right-click in the Queries pane and choose New query > Blank table), name it Margin Target, and enter three columns — MarginTargetLabel (text: 20%, 25%, 30%, 35%, 40%), MarginTargetValue (decimal: 0.20, 0.25, 0.30, 0.35, 0.40), and SortOrder (whole number: 0–4). Close & Apply, then set MarginTargetValue's Sort by column to SortOrder and confirm it does not relate to any other table.
    4. Create the second what-if input using the native feature: click Modeling > New parameter > Numeric range, name it Margin Adjustment %, set Data type to Decimal number, Minimum to -0.1, Maximum to 0.2, Increment to 0.01, and Default to 0, then leave Add slicer to this page checked.
    5. Add two Slicer visuals side by side: drag 'Margin Target'[MarginTargetValue] into the first, and confirm the auto-added Margin Adjustment % slicer sits beside it.
    6. Add two Card visuals to the right of the slicers: drag in [Selected Margin Target] and [Adjusted Gross Margin], with alt text Selected margin target KPI and Adjusted gross margin KPI.
    7. Add a third Card visual below those two for [Gross Margin vs Target], with alt text Margin versus target KPI.
    8. Add a Table visual for the margin detail: drag in DimTerritory[TerritoryName], DimProductCategory[ProductCategory], [Gross Margin %], [Gross Margin vs Target], and [Margin Target Status]. Sort the table ascending by Margin Target Status.
    9. Add a second Table visual for customer ranking: drag in DimCustomer[CustomerName], [Sales Amount], [Customer Sales Rank], and [Is Top 5 Customer].
    FYI — two ways to build a what-if input.
    Margin Target is a small hand-built table loaded through Power Query — useful when you need specific, named choices such as 20% through 40%. Margin Adjustment % uses Modeling > New parameter > Numeric range, which auto-generates a calculated table with a continuous slider from -10% to 20% — better when any value in a range should be selectable. Both feed a SELECTEDVALUE measure ([Selected Margin Target] and [Selected Margin Adjustment %]) that the rest of the model reads from.
  5. Apply conditional formatting to the margin table.
    1. Select the margin detail table you just built and, in the Values field well, click the dropdown arrow on Margin Target Status.
    2. Choose Conditional formatting > Background color.
    3. Set Format style to Field value and choose the [Margin Target Status Color] measure, which returns green for Above target/At target, amber for Near target, and red for Below target.
    4. Click OK, then confirm the Margin Target Status text (not just the color) is still visible in the cell so the rule works for users with color-vision differences.
    FYI — why conditional formatting needs business meaning.
    [Margin Target Status Color] is itself a measure that switches on [Margin Target Status], so the color logic and the text logic can never disagree. If the threshold in [Margin Target Status] were arbitrary, the report would look polished but not guide action — pairing a documented DAX rule with a visible status label keeps the formatting explainable in a code review, not just to the eye.
  6. Create the Customer & Segmentation Detail drillthrough page.
    1. Insert a new page and rename it Customer & Segmentation Detail.
    2. Add a Textbox heading with the bold text Customer & Segmentation Detail.
    3. In the Visualizations pane, find the Drill through field well and drag DimCustomer[CustomerName] into it.
    4. Confirm Keep all filters matches your design intent (leave it on so date, territory, and product context from the source page carries over).
    5. Build the field parameter used on this page: click Modeling > New parameter > Fields, name it Sales Parameters, add [Sales Amount], [Gross Margin], [Gross Margin %], and [Quantity] in that order, and leave Add slicer to this page checked.
    6. Move the auto-added Sales Parameters slicer near the top-left of the page, under the drillthrough context.
    7. Add a Bar chart below the slicer: drag DimProductCategory[ProductCategory] into Y-axis, then drag [Sales Amount], [Gross Margin], [Gross Margin %], and [Quantity] into the Y-axis field well as the parameter's four values (drag the generated Sales Parameters field on top of the four measures so the chart switches between them), and sort descending by [Sales Amount]. Add alt text Bar chart of top customers by sales amount with custom sales tooltip.
    8. Add a Table visual to the right for segment detail: drag in DimCustomer[CustomerName] and [Sales Amount].
    9. Add another Table visual beside it comparing order date vs. ship date: drag in DimTerritory[TerritoryRegion], [Sales by Order Date], and [Sales by Ship Date].
    10. Add a Table visual across the bottom for transactions: drag in FactSales[SalesOrderLineKey], FactSales[OrderDate], DimCustomer[CustomerName], DimProductCategory[ProductCategory], FactSales[Quantity], [Sales Amount], [Gross Margin], and [Gross Margin %]. Add alt text Transaction table showing orders and profitability for the selected customer.
    11. Add a back button with Insert > Buttons > Navigation > Back in the top-left corner.
    12. Test the page: go to another page, right-click a customer value in a table or chart, and choose Drill through > Customer & Segmentation Detail. Confirm the target page opens filtered to that one customer and the Back button returns you to where you started.
    FYI — how drillthrough passes context.
    Drillthrough automatically carries the selected DimCustomer[CustomerName] value to the target page, which is why the detail page opens already filtered to that customer. Keep all filters decides whether the rest of the source-page context — such as date, territory, or product slicers — travels too. Use drillthrough when a user needs a focused deep dive from one data point, not just a different visual state on the same page.
  7. Add bookmarks that show and hide the bar chart on this page.
    1. Open View > Bookmarks to show the Bookmarks pane.
    2. Select a customer in one of the tables so a specific person, such as Sterling Telecom, is filtered on the page, then click Add. Rename the new bookmark Sales Visible. Right-click it and confirm Data and Display are both checked so it captures the filter and the chart's visibility.
    3. Select the bar chart, open View > Selection, and click the eye icon to hide it. With the chart hidden, click Add again and rename the new bookmark Sale Invisible.
    4. Add two small buttons or shapes near the chart. Turn on Action for each, set the action type to Bookmark, and point one at Sales Visible and the other at Sale Invisible.
    5. Test both buttons and confirm only the bar chart's visibility and the customer filter change — nothing else on the page should move.
    FYI — what a bookmark actually captures.
    A bookmark can store more than visual visibility: it can also store filter/slicer state (Data) and the active page (Current page). That is why the checkbox choices matter so much — the Sales Visible and Sale Invisible bookmarks both remember the same customer filter, but toggle whether the bar chart is shown, so clicking between them demonstrates the difference between hiding a visual and re-filtering the page.
  8. Create the Hierarchies, Drill & Groups page.
    1. Insert a new page and rename it Hierarchies, Drill & Groups.
    2. Add a Textbox heading with the bold text Hierarchies, Drill & Groups.
    3. Add a Matrix visual on the left: drag DimProduct's Product Hierarchy (which contains ProductCategory, ProductSubcategory, and ProductName) into the Rows well as a single hierarchy, then drag [Sales Amount] and [Gross Margin %] into Values. Add alt text Matrix using the Product Hierarchy (Category, Subcategory, Product) with drill-down/up and drill-across to Customer Detail enabled.
    4. On the matrix, use the drill icons in its header (or right-click a row) to test Drill down from Category to Subcategory to Product, and Drill up to collapse back — the same visual updates in place as you change levels.
    5. Add a Textbox to the right explaining the three techniques on this page: drill-down/up on the matrix, drill-across via the navigation button below, and named groups in the table.
    6. Add a Table visual under the textbox: drag in DimCustomer[CustomerName], [Sales Amount], and [Customer Sales Group], which buckets customers into Tier 1: $100K+ through Tier 4: Under $10K using a hand-authored DAX measure — the equivalent of Desktop's New Group/New Bin feature. Add alt text Table of customers grouped into named sales tiers using the Customer Sales Group measure.
    7. Add a page navigator at the bottom with Insert > Buttons > Navigator > Page navigator so users can jump to Customer & Segmentation Detail — this is the report-level pattern for "drill-across" when a full drillthrough page isn't wired up for a given field.
    FYI — drill-down/up vs. drill-across vs. drillthrough.
    Drill-down/up changes the level of detail on the same visual using its own hierarchy. Drill-across moves to a different page or visual that continues the same analysis thread — in this lab that's the page navigator button, since a full drillthrough page isn't bound to Product Hierarchy. Drillthrough (from the previous page) is the most targeted option: it opens a dedicated page already filtered to one selected value.
  9. Create the Sales Detail Tooltip report page tooltip.
    1. Insert a new page and rename it Sales Detail Tooltip.
    2. Open the page formatting settings (click the canvas background, then the Format page pane), set Page information > Type to Tooltip, which automatically sizes the canvas to 320 × 240.
    3. Add two small Card visuals side by side: drag in [Sales Amount] and [Gross Margin %], with alt text Tooltip sales card and Tooltip gross margin card.
    4. Add a small Line chart below the cards: drag DimOrderDate[Date] into X-axis and [Sales Amount] into Y-axis, then resize it to fit the remaining space on the small canvas.
    5. Go to Customer & Segmentation Detail, select the bar chart you built there (the one with alt text Bar chart of top customers by sales amount with custom sales tooltip), and in the Format pane set General > Tooltips > Type to Report page and Page to Sales Detail Tooltip.
    6. Hover over that bar chart on Customer & Segmentation Detail to confirm the compact tooltip page appears at the pointer instead of the default hover box.
    FYI — why use a report page tooltip.
    A report page tooltip gives extra context at the exact point of hover without forcing the user to leave the current visual. That makes it ideal for compact details such as a small sales trend or supporting KPIs that would otherwise clutter Executive Overview. Unlike drillthrough, a tooltip is for quick inspection, not navigation — and because the page is marked Hidden in view mode, it never appears as a regular page tab.
  10. Add a bookmark navigator and consistent navigation across pages.
    1. Return to Executive Overview and add a bookmark navigator with Insert > Buttons > Navigator > Bookmark navigator.
    2. In the Format pane under Bookmarks, confirm the navigator lists Sales Visible and Sale Invisible and set the default selected bookmark to Sales Visible. Because that bookmark's Current page option is checked, clicking it also jumps users to Customer & Segmentation Detail already filtered to the demo customer.
    3. Add a page navigator to Executive Overview with Insert > Buttons > Navigator > Page navigator and confirm every other page you built in this lab (Sales & Margin Analysis, Customer & Segmentation Detail, Hierarchies, Drill & Groups) has one in the same position. You will add the same navigator to Security, Navigation & Tooltip when you build that page in Lab 07.
    4. Test navigation from every page so users are not forced to rely on page tabs only.
  11. Create the mobile layout for Executive Overview.
    1. Go to Executive Overview and click View > Mobile layout.
    2. Drag the trend combo chart onto the mobile canvas first, at the top, since trend is the highest-priority visual.
    3. Drag the territory matrix below the trend chart.
    4. Drag only the [Order Count] and [Gross Margin %] cards onto the canvas side by side at the bottom — leave [Sales Amount] and [Sales YoY %] off the phone layout since screen space is limited and the matrix already surfaces sales by territory.
    5. Resize each visual so the touch targets are large enough to tap comfortably.
    FYI — mobile layout is a priority exercise, not a shrink exercise.
    Mobile layout does not automatically include every visual from the desktop canvas — you choose which ones matter most on a phone. Leaving [Sales Amount] and [Sales YoY %] off this layout is a deliberate trade-off: the trend chart and matrix already communicate performance, so the mobile canvas stays uncluttered instead of repeating the same numbers four times.
  12. Run the accessibility review before you finish.
    1. Select each visual across every page you built in this lab and add descriptive alt text in Format > General > Properties > Alt text — reuse the alt text values you entered while building each visual as a checklist.
    2. Open View > Selection and arrange objects into a logical tab order on each page (titles and navigation first, then KPIs, then supporting detail).
    3. Check contrast, confirm every visual title is descriptive, and confirm the Margin Target Status conditional formatting still shows text, not just color.
    4. Use keyboard navigation (Tab and Enter) to confirm the report flow — including drillthrough, tooltip, and bookmark buttons — is understandable without a mouse.
    FYI — accessibility improves usability for everyone.
    Alt text, tab order, contrast, and descriptive titles are not just compliance tasks — they make the report easier to navigate, explain, and present. A clear keyboard path often exposes cluttered layouts or ambiguous labels that also confuse sighted mouse users. Treat accessibility review as a final UX quality check, not as a separate afterthought.

Deeper Understanding Challenge

Build a disconnected metric selector

Compare the native Sales Parameters field parameter you built earlier with a hand-built Power Query selector table and a DAX SWITCH measure — the model already includes an unconnected Metric Parameter table for this exact exercise.

  1. Create a blank Power Query named Metric Parameter.
  2. Use #table to create rows for Sales Amount, Gross Margin, Gross Margin %, and Quantity, each with a SortOrder.
  3. Load the table without relating it to any other table.
  4. Set the Metric column's Sort by column to SortOrder.
  5. Create Selected Metric using SELECTEDVALUE and SWITCH, then add a slicer bound to Metric Parameter[Metric] and a card bound to [Selected Metric] to test it.
let
    Source =
        #table(
            type table [Metric = text, SortOrder = Int64.Type],
            {
                {"Sales Amount", 0},
                {"Gross Margin", 1},
                {"Gross Margin %", 2},
                {"Quantity", 3}
            }
        )
in
    Source
Selected Metric =
VAR SelectedMetric =
    SELECTEDVALUE ( 'Metric Parameter'[Metric], "Sales Amount" )
RETURN
    SWITCH (
        SelectedMetric,
        "Sales Amount", [Sales Amount],
        "Gross Margin", [Gross Margin],
        "Gross Margin %", [Gross Margin %],
        "Quantity", [Quantity],
        [Sales Amount]
    )

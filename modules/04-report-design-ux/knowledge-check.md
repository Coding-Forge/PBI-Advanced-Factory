# Knowledge Check

## Questions

1. Why should report pages be designed around audience and task?
2. When should you use drillthrough?
3. What makes a report page tooltip effective?
4. What bookmark settings can cause unexpected behavior?
5. Why should every guided report experience include a reset path?
6. What is one risk of overusing conditional formatting?
7. Why should mobile layouts be designed separately from desktop layouts?
8. What are three accessibility checks every report should include?
9. Why are personalized visuals marked **Verify for Gov**?
10. Why should AI visuals be optional for Azure Government delivery?
11. What problem do field parameters solve in a report experience?

## Answer key

1. Audience-driven design helps users answer their specific questions faster and avoids pages that try to serve every use case poorly.
2. Use drillthrough when users need detail about a selected entity, such as a customer, product, territory, or transaction group.
3. A good tooltip is focused, compact, contextual, and does not duplicate the main page.
4. Capturing data, display, or current page unintentionally can make bookmarks change filters or navigation unexpectedly.
5. A reset path helps users recover from complex filter or bookmark states.
6. Too much conditional formatting can distract users and make truly important exceptions less visible.
7. Mobile layouts need fewer visuals, larger touch targets, and different prioritization than desktop pages.
8. Accessibility checks include alt text, tab order, contrast, descriptive titles, keyboard navigation, and avoiding color-only meaning.
9. Personalized visuals depend on Service availability and tenant settings that can differ in Azure Government.
10. AI visual availability may lag, vary by tenant, or be unavailable in sovereign clouds, so Gov labs need a non-AI path.
11. Field parameters let report users switch between approved measures or dimensions in a visual without duplicating report pages or creating uncontrolled self-service behavior.

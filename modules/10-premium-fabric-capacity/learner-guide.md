# Learner Guide

## What you will learn

You will learn how to compare Power BI licensing and capacity options and how capacity-aware features affect architecture, operations, and governance.

## Scenario

Contoso Advanced Manufacturing is planning a larger enterprise analytics platform. Some teams need standard reporting, some need large shared semantic models, and some want Fabric-integrated analytics. You will evaluate architecture options and identify what must be validated for Azure Government delivery.

## Prerequisites

- Understanding of Power BI Service workspaces and semantic models.
- Understanding of refresh and performance concepts.
- Optional access to Premium, PPU, or Fabric capacity for hands-on extensions.

## Azure Government readiness

This module is mostly architecture-focused. Fabric capacity, Direct Lake, OneLake, Lakehouse, Warehouse, Semantic Link, and autoscale are **Commercial-focused / Verify for Gov**. XMLA, paginated reports, large semantic models, and capacity metrics are **Verify for Gov**.

## Power BI project format

Power BI reports and models should remain PBIP source projects in git. PBIX files are optional generated artifacts.

## Tasks

1. Compare licensing and capacity options.
2. Review XMLA endpoint use cases where available.
3. Review paginated report use cases where available.
4. Review large semantic model settings where available.
5. Review Fabric architecture concepts.
6. Review capacity metrics and throttling concepts.
7. Select a Gov-safe architecture path.

## Validate your work

Your completed work should include:

- Capacity option comparison notes.
- Feature availability labels.
- Optional hands-on validation notes.
- Gov-safe alternate architecture.
- Capacity metrics/throttling interpretation notes.

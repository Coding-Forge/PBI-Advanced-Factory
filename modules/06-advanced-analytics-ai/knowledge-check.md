# Knowledge Check

## Questions

1. Why are what-if parameters considered Gov-ready?
2. What is a good use case for decomposition tree?
3. Why should forecasting results be interpreted carefully?
4. What is one non-AI way to identify exceptions in a trend?
5. Why are key influencers marked **Verify for Gov**?
6. What must be validated before using Python or R visuals?
7. What must be validated before integrating Azure Machine Learning?
8. Why should Copilot be treated conceptually unless validated?
9. What should a Gov-safe alternate path include?
10. Why should AI-generated output require human review?

## Answer key

1. What-if parameters are Desktop modeling/reporting features that do not require AI services.
2. Decomposition tree is useful for exploring drivers behind a metric across multiple explanatory dimensions.
3. Forecasts depend on data quality, history, seasonality, and assumptions; they are not guaranteed predictions.
4. Use DAX thresholds, rolling averages, standard deviation bands, or conditional formatting.
5. Key influencers is an AI visual, and availability can differ by cloud, tenant settings, and Service support.
6. Validate local runtime, package policy, Service support, data privacy, and customer workstation rules.
7. Validate Azure cloud/region, identity, network, workspace, endpoint, data residency, and governance requirements.
8. Copilot availability depends on cloud, tenant, capacity, licensing, region, and admin settings.
9. It should identify the learning goal, unavailable feature, alternate manual/native approach, and validation notes.
10. AI-generated output can be incomplete or incorrect and must be checked against trusted data and business context.

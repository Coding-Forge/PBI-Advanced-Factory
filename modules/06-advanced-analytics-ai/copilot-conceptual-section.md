# Copilot in Power BI and Fabric: Conceptual Section

> **Azure Government note:** Copilot in Power BI/Fabric is marked **Commercial-focused / Verify for Gov**. Do not make Copilot a required hands-on lab unless the target tenant, capacity, licensing, data boundary, and admin settings have been validated.

## Conceptual learning goals

Learners should understand:

- Where Copilot may assist with report authoring, summarization, measure creation, and data exploration.
- Why Copilot availability depends on tenant, capacity, licensing, region, and admin settings.
- Why organizational data governance and sensitivity controls matter.
- Why AI-generated outputs require human review.
- How to provide a non-Copilot path for Gov or restricted tenants.

## Suggested discussion topics

- What user problems could Copilot help with?
- Which data should not be used in AI-assisted workflows?
- Who approves Copilot usage in a tenant?
- How should generated DAX or narrative summaries be reviewed?
- What is the fallback when Copilot is unavailable?

## Non-live demo option

If Copilot is unavailable, use static screenshots or written examples that show:

1. A user asks for a summary of sales performance.
2. Copilot drafts a response.
3. The report author validates numbers against visuals and measures.
4. The author edits the narrative for accuracy and context.
5. The team documents that Copilot output is assistive, not authoritative.

## Governance reminders

- Validate data residency and compliance requirements.
- Validate sensitivity label behavior.
- Validate tenant settings.
- Validate capacity and licensing.
- Require human review of AI-generated content.
- Provide a non-AI workflow for restricted environments.

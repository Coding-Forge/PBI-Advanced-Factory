# Endorsement Governance Checklist

Use this checklist before marking content as Promoted or Certified.

## Ownership

- [ ] Business owner identified.
- [ ] Technical owner identified.
- [ ] Support contact identified.
- [ ] Workspace owner identified.
- [ ] Refresh owner identified.

## Model quality

- [ ] Star schema or approved model pattern reviewed.
- [ ] Measures are named and formatted consistently.
- [ ] Unused fields are removed or hidden.
- [ ] RLS/OLS requirements are reviewed.
- [ ] Sensitivity label requirement is reviewed.
- [ ] Performance baseline is acceptable.

## Data and refresh

- [ ] Data sources are documented.
- [ ] Credentials are configured appropriately.
- [ ] Gateway mapping is documented where needed.
- [ ] Refresh schedule is documented.
- [ ] Refresh history is reviewed.
- [ ] Data quality issues are documented.

## Access and distribution

- [ ] Workspace roles are reviewed.
- [ ] App audience or consumer list is reviewed.
- [ ] Build permission is reviewed.
- [ ] External sharing policy is reviewed.
- [ ] Export settings are reviewed.

## Azure Government validation

- [ ] Tenant cloud and workspace are documented.
- [ ] App distribution is validated.
- [ ] App audiences are validated or marked **Verify for Gov**.
- [ ] Gateway configuration is validated or marked **Verify for Gov**.
- [ ] Deployment pipelines are validated or marked **Verify for Gov**.
- [ ] Cloud connections are validated or marked **Verify for Gov**.

## Endorsement decision

- [ ] Promoted is appropriate for discoverability.
- [ ] Certified is appropriate for authoritative enterprise reuse.
- [ ] Certification approval evidence is recorded.
- [ ] Review cadence is defined.
